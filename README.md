# parallel_request

Выгрузка данных из ClickHouse THEATRE в `pandas.DataFrame`:

```python
from parallel_request import extract

df = extract(
    query,
    "2026-05-01",
    "2026-05-17",
    chunk_type="day",
    workers=4,
)
```

Функция делит период на интервалы, выполняет запросы параллельно и возвращает
объединённый DataFrame в память. Серверы и база THEATRE уже настроены.
Результат автоматически в файлы не записывается.

## 1. Установите пакет в Jupyter

Нужен Python 3.10 или новее. Скачайте проект и выполните в ячейке ноутбука,
указав путь к его папке — той, где находится `pyproject.toml`:

```python
%pip install "D:/work/parallel_request"
```

Зависимости установятся автоматически. `%pip` использует окружение текущего
ядра Jupyter. Если пакет уже был импортирован до переустановки, перезапустите ядро.

Для работы с клонированным проектом можно открыть [quickstart.ipynb](quickstart.ipynb)
в корне репозитория: в нём уже есть ячейки установки и выгрузки.

## 2. Укажите реквизиты THEATRE

Создайте `.env` в **рабочей папке ноутбука**:

```dotenv
THEATRE_LOGIN_RU=your_login
THEATRE_PASS_RU=your_password
```

Рабочую папку можно посмотреть так:

```python
from pathlib import Path

Path.cwd()
```

По умолчанию `extract()` читает `.env` именно из этой папки, независимо от того,
где установлен пакет. Если файл уже заполнен, менять его не нужно.
Для подключения требуется сетевой доступ к THEATRE.

Другой путь можно передать через `env_file="D:/settings/theatre.env"`.
Также поддерживаются переменные окружения `THEATRE_LOGIN_RU` и `THEATRE_PASS_RU`:
они имеют приоритет над файлом. `env_file=None` полностью отключает чтение файла.
При импорте пакета реквизиты не читаются и подключения не открываются.

## 3. Выполните запрос

Замените `your_table` и `created_at` на нужную таблицу и её столбец с датой:

```python
from parallel_request import extract

query = """
SELECT *
FROM your_table
WHERE created_at >= {start_date}
  AND created_at < {end_date}
"""

df = extract(
    query=query,
    start_date="2026-05-01",
    end_date="2026-05-17",
    chunk_type="day",  # Делить период на интервалы по одному дню.
    workers=4,         # Выполнять до четырёх запросов одновременно.
)

df.head()
```

В `df` находится обычный `pandas.DataFrame`. Можно фильтровать строки,
группировать данные, объединять его с другими таблицами и передавать в функции.

В этом примере получится **16 дневных чанков**, которые выполняются максимум
**четырьмя воркерами одновременно**. Каждый воркер держит отдельное подключение
и после завершения своего запроса берёт следующий чанк из очереди.

В примере выгружаются данные **с 1 по 16 мая включительно**.
Начальная дата включается, конечная — нет. Чтобы включить весь последний день,
укажите в `end_date` начало следующего дня.

Оба параметра SQL — `{start_date}` и `{end_date}` — обязательны и пишутся
**без кавычек**. Значения дат передаются драйверу отдельно.

## 4. Настройте количество воркеров и размер чанка

Оба параметра выбираете вы при вызове `extract()`:

- **`workers`** — сколько запросов можно выполнять одновременно суммарно на всех
  серверах. Например, `workers=1` — последовательно, `workers=4` — до четырёх
  запросов одновременно. Это общий лимит, а не число воркеров на каждый сервер.
- **`chunk_type`** — на какие временные интервалы делить выгрузку. На каждый чанк
  выполняется отдельный SQL-запрос со своими границами дат.

Например, выгрузка мая по неделям с четырьмя воркерами:

```python
df = extract(
    query,
    "2026-05-01",
    "2026-06-01",
    chunk_type="week",
    workers=4,
)
```

| `chunk_type` | Как делится период |
| --- | --- |
| `"hour"` | По одному часу от начала периода. |
| `"day"` | По одному дню от начала периода. |
| `"week"` | По семь дней от начала периода. |
| `"month"` | По границам календарных месяцев. |
| `"quarter"` | По границам календарных кварталов. |
| `"year"` | По границам календарных лет. |

Если не указывать эти настройки, используются **`chunk_type="day"` и `workers=8`**.
Реальное число воркеров не превышает число чанков. Например, для периода
1–16 мая с `chunk_type="month"` получится один чанк и будет работать один воркер,
даже если указать `workers=8`. Размер чанка автоматически не уменьшается.

### Все параметры extract()

| Параметр | Значение |
| --- | --- |
| `query` | SQL-запрос с двумя параметрами дат. |
| `start_date` | Начало периода. Строка ISO, объект `date` или `datetime`. |
| `end_date` | Исключающая граница конца периода. Те же форматы. |
| `chunk_type` | `hour`, `day`, `week`, `month`, `quarter`, `year`. По умолчанию `day`. |
| `workers` | Общий максимум одновременных запросов на все серверы. Положительное целое число, по умолчанию 8. |
| `env_file` | Путь к файлу реквизитов. По умолчанию `.env`; `None` — только окружение. |

Строки дат могут содержать время: `"2026-05-01T10:30:00"`.
Обе границы должны быть либо с часовым поясом, либо без него.

Первый и последний интервалы ограничиваются заданными `start_date` и `end_date`.

## Поведение функции

- Вызов ожидает завершения запросов и возвращает один DataFrame.
- Строки объединяются в порядке завершения интервалов, без общей сортировки.
  При необходимости используйте `df.sort_values(...)`.
- SQL-агрегации, `LIMIT` и `ORDER BY` выполняются отдельно внутри каждого
  интервала; объединение результатов не пересчитывает общий итог.
- При ошибке выбрасывается исключение. Частичный результат не возвращается.
- В консоли отображается ход выполнения. При прерывании выдача новых интервалов
  прекращается, а уже начатые запросы завершаются перед закрытием соединений.
